Web UI特有の「プロンプト自動補正（Prompt Enhancement）」最近の画像生成Webサービス（Higgsfield等）は、ユーザーが入力したプロンプトをそのままモデルに渡さず、裏でLLMを使って「画像生成AIが最も高画質を出せる長文プロンプト」に自動で書き換えてから生成しています。Web UI: 入力した短い指示を、裏で数倍の長さの高品質プロンプトに変換して生成している。MCP経由: 送った文字列が「生データ（Raw）」のまま直接モデルに渡るため、補正がかからずシンプルな生成結果になってしまう。2. 自動ポストプロセス（アップスケール・画質補正）の有無Web画面で生成した場合、モデル本体が生成した画像に対して、自動的に以下のような仕上げ処理が施されていることがあります。Face Restoration（顔の崩れを自動補正）Upscaler / Hi-Res Fix（2倍や4倍に高解像度化し、線をクッキリさせる）MCP経由のAPIリクエストでは、これらのオプションパラメータ（upscale: true など）を明示的に渡さない限り、未補正の生画像（低解像度・生出力）が返ってくるため、クオリティが低く見えてしまいます。3. パラメータのデフォルト値の違い（解像度・ステップ数・CFG）MCPのツール定義（JSON Schema）で設定されているデフォルト値が、Web UIよりも低く設定されている可能性があります。設定項目Web UI の内部デフォルトMCPでのよくあるデフォルト値解像度1024 × 1024 (HD)512 × 512 (標準)生成ステップ数 (Steps)30 〜 50 ステップ15 〜 20 ステップモデルの選択nano-banana-2 (最新)nano-banana-1 や旧バージョンに固定されている解像度やステップ数が低いと、ベクターイラストのような「クッキリした線」や「滑らかな塗りの質感」が出ずにボヤっとした印象になります。4. MCPを実行している Agent (Claude等) によるプロンプト改変CursorやClaude DesktopなどのAIエージェントに「MCPでこのプロンプトで画像を作って」と頼んだ際、Agentが気を利かせてプロンプトを要約したり、ツールへ渡す引数（JSON）を勝手に書き換えてしまっているケースがよくあります。MCPでWebレベルのクオリティを出すための対策もしMCPのコードや呼び出し方を調整できる場合は、以下のポイントを試してみてください。モデルIDを明示的に指定するMCPパラメータで model: "nano-banana-2" や /nano_banana_flash が正しく指定されているか確認する。解像度とアスペクト比を高く指定するwidth: 1024, height: 1024 や quality: "hd" などのパラメータがツールに用意されていれば明示的に渡す。Webで使われているプロンプトを自前で拡張するプロンプトの末尾に、画質を高める表現（masterpiece, 8k resolution, vector art, extremely detailed, crisp clean lines など）を意識的に足してあげる。Agent（Cursor等）のログを確認するAgentが実際どんなJSON引数をMCPツールに渡しているかログを見て、自分のプロンプトが勝手に削られていないかチェックする。
